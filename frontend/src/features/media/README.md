# Media 创作工作区

本目录从已有个人创作工作区提取，保留完整操作的状态与生命周期。HTTP、流解析与任务协议复用独立应用内的 `lib/media-*`。

| 入口 | 当前职责 |
|---|---|
| `index.tsx` | 页面、唯一认证/会话/消息状态 owner、视觉输入 owner 与跨操作 busy 协调；把接受的图片任务接入当前会话 |
| `chat/controller.ts` | 对话流的开始、状态/增量转发、错误/完成回调、取消与会话版本隔离；页面继续独占会话、消息和视觉上下文状态 |
| `chat/controller.test.ts` | 合成流回归：loading/status 清理、部分输出错误、显式再次发送恢复、取消、切会话后的迟到回调隔离 |
| `image-jobs/controller.ts` | 图片任务轮询、重复结果去重、异步会话版本保护、取消/释放，以及作品消息的转存状态更新；HTTP 与任务协议继续复用 `lib/media-jobs` |
| `image-jobs/controller.test.ts` | 任务生命周期回归：重复结果、原图在转存完成/失败后的保留、过期会话响应、取消轮询 |
| `image-jobs/submission-controller.ts` | 确认提交、意图指纹/request ID、单次在途互斥与过期会话隔离；页面仍是会话状态唯一 owner，提交 POST 不自动重试，也不伪称可被客户端撤回 |
| `image-jobs/submission-controller.test.ts` | 合成提交回归：不确定结果后的显式同 ID 重试、编辑意图换 ID、并发确认互斥、切会话后的迟到响应 |
| `reference/controller.ts` / `useReferenceUpload.ts` | 私有参考图上传、卡片绑定/移除、输入框图片清除、取消、预览 URL 与请求清理；只通过带会话版本的命令提交结果 |
| `session/visual-state.ts` / `useMediaVisualState.ts` | 当前图片、待发送附件和待参考图输入的唯一记录；版本保护失败清除回滚，防止覆盖后来的图片 |
| `session/operation-failure.ts` | 当前 401 与旧会话/旧令牌错误的归属判断；API 清掉令牌后仍保留当前登录失效反馈 |
| `ReferenceUploadProgress.tsx` | 原有上传预览与处理中反馈 |

上传模块只管理临时选择和传输，不建立第二份可修改的会话图片、卡片或消息。文件选择时捕获会话/认证版本；切会话、换令牌、取消或卸载后，不启动旧上传的卡片写回或聊天续接。请求已到服务端时取消不能撤回其原会话副作用，客户端忽略过期结果，不改投新会话。

卡片上传仍使用 `activate_context=false`，先上传，再持久化卡片，成功后更新原消息记录。输入框上传向唯一图片 owner 提交；原有“上传后继续此前输入”由页面使用有效回执协调，模块不直接调用聊天或生图。清除失败只恢复未被后来操作修改的图片。保持原进度、错误、禁用与显式重试入口，不自动重发付费请求。`media-client` 的卡片更新与清除仅新增可选 AbortSignal，端点、请求正文与无 signal 调用兼容。

图片任务提交模块只接收页面已经验证过的方案、用户选项、有效视觉输入和认证/会话快照；它负责为同一方案意图保持稳定 request ID，并串行化确认提交。连接中断等结果不确定时不会自动重试；用户再次确认同一意图会沿用 request ID，改动意图会生成新 ID。切会话或离页会忽略迟到回包，**不会取消已发往服务端的 POST 或已接受的图片任务**；回到原会话仍由现有活动任务恢复逻辑读取。

对话流控制器只管理一次流式请求的异步生命周期。页面仍在调用前组装完整请求，并通过端口回调更新唯一消息/视觉状态 owner；错误保留已到达的部分文本，明确的下一次发送可以恢复。切会话或离页会中止客户端读取并屏蔽迟到状态，不代表服务端撤销已经收到的聊天请求。
